## 劇情

Ami 先到新竹了，在車站出口等你。她用 LINE 說：搭台鐵幾點幾分的自強號，一定要有座位，不要搭區間車。主角在台北車站售票窗口買票 → 售票員可能說錯 → 付錢找錢 → 檢查車票有沒有印錯 → 進閘門 → 看電子看板找月台 → 找車廂 → 找座位（有時有人坐在你的位子上）。

## 關卡流程（ORDER）

START → COUNTER（說去哪裡、哪一種車、幾點）→ **SOLD（40%：這班對號座位賣完，只剩無座票；要問下一班有座位的自強號，開車時間 +30 分）** → **TK_CHECK（售票員複誦：目的地／車種／開車時間，45% 說錯一項）** → **PAY（報價，45% 多算一張）→ PAY_FIX → CHANGE（找錢，40% 找錯）** → **TICKET（車票印出來，40% 印錯目的地或時間）** → GATE（用車票進站，不是刷悠遊卡）→ PLATFORM（看板上三班車，選自己的月台）→ CAR（選車廂）→ **SEAT（45% 有人坐在你的位子上）** → END → RESULT。

## 對方出錯點與機率

| 關卡 | 錯誤機率 | 怎麼出錯 | 正解 |
|---|---|---|---|
| SOLD | 40% 出現 | 原本那班只剩無座票 | 問下一班有座位的自強號（買無座票、改搭區間車都是錯） |
| TK_CHECK | 45% | 目的地／車種（說成區間車）／開車時間（+30 分）其中一項說錯 | 沒錯→「對，沒錯。」；錯→有禮貌說出正確那一項 |
| PAY | 45% | 多算一張票（253 → 506） | 沒錯→給鈔票；錯→指出應該是 253 元 |
| CHANGE | 40% | 找的錢差 ±10 或 ±20 | 沒錯→謝謝；錯→指出應找的金額 |
| TICKET | 40% | 目的地或時間印錯 | 沒錯→謝謝；錯→指出正確的並請他重印 |
| SEAT | 45% | 有乘客坐在你的位子上 | 有人→有禮貌地說「這是我的位子，我的票是…」；沒人→坐下 |

三個選項固定寫法：①沒錯／謝謝 ②有禮貌指出問題（對方沒錯時，內容是錯的數字）③沒禮貌（永遠錯）。共用的 `catchState`／`payStates` 讓玩家不能「收下錯誤」往前走，所以好壞結局（錯誤 ≤ 2 次好結局）一定和最後實際拿到的東西一致。

## 價錢與計算邏輯

- 票價：台北→新竹自強號 253 元（區間車 163 元，只放在說明，遊戲裡沒有買區間車）。**這個價錢來自 TVBS 一篇「調漲後」的票價表，不確定現在實收，待確認。**
- 多算時 `said = 506`，你給的鈔票用 `billFor()`：≤100 → 100、≤200 → 200、≤500 → 500、其餘 1000；找錢＝你給的 − 真正票價。
- 時間：Ami 說的時間 `t1`（08:10–15:50，整點後 10／30／50 分）；賣完時實際搭 `t1+30`。念法 `tmZh()`：「十點半」「九點十分」。
- 車次（107、113、121…）、車廂（3–7 車）、座位（11–28 號）、月台（2–5 號）都是隨機的，念數字用 `zhNum`／`zhDigits`。

## 正解怎麼判定

一般關卡：選錯扣十分並留在原關。選項用 `rotOf` 隨機排。GATE 的錯誤答案是「刷悠遊卡」「直接走進去」；PLATFORM 看板有三班車（你的、同時間往花蓮的自強號、比較早往新竹的區間車），要用車次、車種、目的地一起判斷。
