## 劇情

玩家的手機門號沒有網路了。Ami 用 LINE 說：去電信行辦一張新的預付卡，方案每局隨機（三天十二G 三百九十九元／三十天二十四G 五百九十九元／三十天六十G 九百九十九元），帶護照和居留證，店員複誦方案、算錢要仔細聽，拿到新卡也要對門號。玩家走進電信行 → 說要辦預付卡 → 給兩種證件 → 選方案 → 核對店員複誦 → 付錢找錢 → 拿到新卡、核對店員唸的新門號 → 手機沒訊號請店員幫忙 → 問以後怎麼儲值 → 傳訊息給 Ami。
（總清單的重點「辦門號、儲值、手機出問題」都有：辦門號＝DOCS／PLAN／REPEAT／SIM，儲值＝PAY 付費與 TOPUP，手機出問題＝NOSIGNAL。）

## 關卡流程（ORDER）

START → ENTER（說要辦預付卡）→ DOCS（護照＋居留證）→ PLAN（選方案）→ **REPEAT（店員複誦方案，45% 說成另一個方案）** → **PAY（報價，45% 多算一項沒要的）** → PAY_FIX（算錯時重付）→ **CHANGE（找錢，約 40% 找錯）** → **SIM（店員唸新門號，45% 最後兩碼唸反）** → NOSIGNAL（手機沒訊號）→ TOPUP（問怎麼儲值）→ END → RESULT。

## 對方出錯點與機率

| 關卡 | 錯誤機率 | 怎麼出錯 | 正解 |
|---|---|---|---|
| REPEAT | 45% | 店員複誦成另一個方案（天數／流量／價錢都不同） | 沒錯→「對，麻煩你了。」；錯→「不好意思，我要的是○○，○元。」 |
| PAY | 45% | 多算一項沒要的加購品（保護貼 150 元或備用 SIM 卡 100 元） | 沒錯→給錢；錯→「不好意思，好像算錯了，應該是○元吧？」 |
| CHANGE | 40% | 找的錢差 ±10 或 ±20 元 | 沒錯→「好，謝謝。」；錯→「不好意思，好像找錯了，應該找○元吧？」 |
| SIM | 45% | 唸門號時最後兩碼唸反（單據上的才是對的） | 沒錯→「好，沒問題，謝謝。」；錯→「不好意思，單據上的門號最後三碼是○○○。」 |

三個選項固定寫法：①沒錯／謝謝　②有禮貌指出問題（對方沒錯時，內容是錯的）　③沒禮貌（永遠錯）。四關都用共用的 `catchState`（PAY／PAY_FIX／CHANGE 由 `payStates`）：玩家不能「收下錯誤」往前走，所以好壞結局（錯誤 ≤ 2 次好結局）一定和最後實際拿到的東西一致（對的方案、對的金額、對的門號）。
其他關卡是固定正解，錯誤答案：ENTER（要辦月租約、說手機壞了要修）；DOCS（只帶居留證＋手機照片、質疑為什麼要兩種證件）；PLAN（選了另外兩個方案）；NOSIGNAL（罵卡是壞的要退錢、自己把手機重設成原廠）；TOPUP（以為會自動從銀行扣款、要店員現在儲值五千元）。

## 價錢與計算邏輯

- 價錢＝選到的方案價格 `plan.p`（399／599／999）。用共用的 `initPay`：`t.said` 是店員報的價（可能多算），`t.total` 是真正該付的。
- 玩家付的鈔票 `billFor`：≤500 付五百，≤900 付一千，其他付兩千（所以 999 元的方案付兩千元，找一千零一元）。
- 找零 `t.change＝bill−total`；店員找錯時差 ±10／±20 元。對方說的和真的分開記（`said`／`total`、`given`／`change`、`repPlan`／`plan`、`numSaid`／`num`）。
- 門號：09 開頭十碼（虛構），念成四碼、三碼、三碼各一組（`phoneSay`）。
