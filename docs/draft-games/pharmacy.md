## 劇情

Ami 感冒了（每局隨機：喉嚨痛＋流鼻水，或咳嗽＋流鼻水；都沒有發燒），在家休息，用 LINE 請主角去藥局買「綜合感冒藥」和「一盒喉糖」，說她對藥沒有過敏、沒有吃別的藥，並交代要看藥盒、問清楚怎麼吃。主角走進藥局 → 跟藥師說明狀況 → 說症狀 → 回答過敏／別的藥 → 問怎麼吃 → 核對藥盒 → 核對藥師說的吃法和說明書 → 聽注意事項 → 結帳（核對價錢、付錢、核對找錢）→ 把藥送到 Ami 家。

## 關卡流程（ORDER）

START → ENTER（有禮貌地說朋友感冒）→ SYMPTOM（說症狀）→ ALLERGY（沒有過敏、沒吃別的藥）→ ASK（問怎麼吃、一天幾次）→ **PICK（藥師拿藥，45% 拿錯盒）→ DOSE（藥師口頭說吃法，40% 和說明書不一樣）** → WARN（注意事項：不要喝酒、三天沒好看醫生）→ **PAY（報價，45% 多算沒買的東西）→ PAY_FIX → CHANGE（找錢，40% 找錯）** → END → RESULT。

## 對方出錯點與機率

| 關卡 | 錯誤機率 | 怎麼出錯 | 正解 |
|---|---|---|---|
| PICK | 45% | 藥師說「這是綜合感冒藥」，但藥盒上寫「腸胃藥」或「止痛藥」 | 沒錯→「好，謝謝。」；錯→「不好意思，這盒是○○，我要的是綜合感冒藥。」 |
| DOSE | 40% | 藥師口頭說的吃法（飯前／一次兩包／一天兩次，三種隨機挑一種）和說明書（一天三次，飯後吃，一次一包）不同 | 沒錯→「好，我知道了，謝謝。」；錯→「不好意思，說明書上寫的是一天三次，飯後吃，一次一包，對嗎？」 |
| PAY | 45% | 多算沒買的東西：一罐維他命（一百元）或一瓶漱口水（八十元） | 沒錯→給鈔票；錯→指出應該是幾元 |
| CHANGE | 40% | 找的錢差 ±10 或 ±20 | 沒錯→謝謝；錯→指出應找的金額 |

三個選項固定寫法：①沒錯／謝謝 ②有禮貌指出問題（對方沒錯時，內容是錯的）③沒禮貌（永遠錯）。PICK、DOSE、PAY、CHANGE 用共用的 `catchState`／`payStates`：玩家不能「收下錯誤」往前走，所以好壞結局（錯誤 ≤ 2 次好結局）一定和最後實際拿到的東西一致（拿到的是感冒藥、記到的吃法是說明書上的、付的錢和找的錢）。
其他關卡（ENTER、SYMPTOM、ALLERGY、ASK、WARN）是固定正解，錯誤答案：命令藥師、自己亂拿藥；說成肚子痛（症狀說錯）、說「藥師你自己看」；說不知道有沒有過敏、回嗆；說「我自己看就好」、「吃多少都可以」；說「喝一點啤酒沒關係」、「不用看醫生」。

## 價錢與計算邏輯

- 綜合感冒藥每局隨機 120／150／180 元；喉糖 60 元。總價＝兩者相加（180～240 元）。**這些價錢是我設定的，沒有官方來源，待確認。**
- 價目畫面（`billHTML`）列出兩項標價，讓玩家自己加總。多算項目（維他命 100 元、漱口水 80 元）是玩家沒買的，所以報價高了就是錯。
- 你給的鈔票用 `billFor()`：總價 ≤200 → 兩百元，其餘五百元；找錢＝你給的 − 總價（共用 `initPay` 算）。
- 我的狀況寫「一百元、兩百元和五百元的鈔票，還有零錢」。

## 查證來源

- 衛福部食藥署〈感冒用藥注意事項〉<https://mohw.gov.tw/cp-2633-10539-1.html>：藥品分成藥、指示藥（在醫師、藥師或藥劑生指示下使用）、處方藥；買藥前先諮詢藥師、用藥前詳讀外盒或說明書；服用綜合感冒藥期間避免飲酒；自行服藥三天以上沒有改善或惡化要盡快就醫。（遊戲的 ASK、WARN 就是照這份寫的。）
