## 劇情

Ami 先到目的地了（每局隨機：國父紀念館、松山機場、士林夜市、台北一零一），用 LINE 說「現在是下午，你在路邊招手攔一台計程車過來就可以了，上車要跟司機說清楚去哪裡，付錢的時候看計費表上的車資」。主角在路邊招手 → 上車說目的地 → 司機複誦（可能聽成像的地方）→ 繫安全帶 → 看計費表（可能忘了跳表）→ 快到了說在哪裡下車 → 付錢（可能多算）→ 找錢（可能找錯）→ 下車前看後面來車、拿好東西 → Ami 迎接。

## 關卡流程（ORDER）

START → HAIL（看「空車」燈、站路邊招手）→ TELL（上車，說目的地，要有禮貌）→ **DEST_CHECK（司機複誦，45% 聽成像的地方）** → BELT（繫安全帶）→ **METER（看計費表，40% 司機忘了跳表）** → STOP（說在前面路口停）→ **PAY（報價，45% 多算夜間加成或小費 20 元）→ PAY_FIX → CHANGE（找錢，40% 找錯）** → EXIT（下車前看後面、拿好東西）→ END → RESULT。

## 對方出錯點與機率

| 關卡 | 錯誤機率 | 怎麼出錯 | 正解 |
|---|---|---|---|
| DEST_CHECK | 45% | 司機把目的地聽成「聽起來像」的地方（國父紀念館→中正紀念堂、松山機場→松山車站、士林夜市→士林官邸、台北一零一→台北車站） | 沒錯→「對，沒錯，謝謝。」；錯→「不好意思，我要去○○。」 |
| METER | 40% | 計費表沒有跳（顯示 — — —） | 沒錯→「好，謝謝。」；錯→「不好意思，請問可以跳表嗎？」 |
| PAY | 45% | 多算二十元：「夜間加成」（現在是下午，不能加）或「小費」（不用給） | 沒錯→給鈔票；錯→指出應該是幾元（計費表上的數字） |
| CHANGE | 40% | 找的錢差 ±10 或 ±20 | 沒錯→謝謝；錯→指出應找的金額 |

三個選項固定寫法：①沒錯／謝謝 ②有禮貌指出問題（對方沒錯時，內容是錯的）③沒禮貌（永遠錯）。共用的 `catchState`／`payStates` 讓玩家不能「收下錯誤」往前走，所以好壞結局（錯誤 ≤ 2 次好結局）一定和最後實際拿到的東西一致（目的地、有跳表、付的錢、找的錢）。
其他關卡（HAIL、TELL、BELT、STOP、EXIT）是固定正解，錯誤答案：跑到馬路中間招手、招沒亮「空車」燈的車；說錯地點或催司機「快開」；說後座不用繫安全帶、等司機提醒再繫；叫司機在車道中間立刻停、不說地點；直接開車門（沒看後面）、東西留在車上。

## 價錢與計算邏輯

- 車資＝起跳價 85 元 ＋ 5 元 × 段數（段數 10–22，所以 135～195 元）。**起跳價與每段 5 元是依印象，台北市現行費率沒有查到官方數字，待確認。**
- 計費表畫面（`meterHTML`）：PAY／PAY_FIX／CHANGE 時顯示真正的車資 `t.total`；司機說的 `t.said` 可能多二十元。你給的鈔票用 `billFor()`：≤200 → 兩百元，其餘五百元；找錢＝你給的 − 計費表上的車資（共用 `initPay` 算）。
- 我的狀況寫「一百元、兩百元和五百元的鈔票，還有零錢」。

## 正解怎麼判定

一般關卡：選錯扣十分並留在原關。選項用 `rotOf` 隨機排。付錢三關用共用的 `payStates`（付錢不夠會被說「這樣不夠」）。
