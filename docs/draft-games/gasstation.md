## 劇情

Ami 的機車沒油了，用 LINE 請玩家把車騎去加油站：每局隨機要加 92 或 95 無鉛汽油，金額一百五十、兩百、兩百五或三百元；玩家身上只有一張五百元鈔票。流程：停車熄火、開油箱蓋 → 對加油員說油種和金額 → 加油員複誦（可能聽錯）→ 坐在車上等加油 → 加油員報價（可能多報）→ 付五百元 → 核對找的錢（可能找錯）→ 核對發票金額（可能印錯）→ 蓋好油箱蓋、收好發票離開 → 傳訊息給 Ami。
（總清單重點「騎機車加油，說油的種類（92／95）和金額，核對發票和找錢」。）

## 關卡流程（ORDER）

START → ARRIVE（熄火、停好、開油箱蓋）→ ORDER（說油種和金額）→ **CONFIRM（加油員複誦，45% 聽錯）** → FILL（等加油）→ **PAY（報價，45% 多報）** → PAY_FIX（報價多報被抓到後，重新付錢）→ **CHANGE（找錢，找錢時 40% 找錯）** → **INVOICE（發票金額，40% 印錯）** → CLOSE（蓋油箱蓋、收發票）→ END → RESULT。

## 對方出錯點與機率

| 關卡 | 錯誤機率 | 怎麼出錯 | 正解 |
|---|---|---|---|
| CONFIRM | 45% | 加油員把油種（92↔95）或金額聽成別的（二選一，各一半） | 沒錯→「對，沒錯，謝謝。」；錯→「不好意思，我要的是○無鉛，加○元。」 |
| PAY | 45% | 加油員報的錢比加油機螢幕多（多報五十或三十元） | 沒錯→「給你五百元。」；錯→「不好意思，好像算錯了，應該是○元吧？」 |
| CHANGE | 40% | 找的錢多或少十或二十元 | 沒錯→「好，謝謝。」；錯→「不好意思，好像找錯了，應該找○元吧？」 |
| INVOICE | 40% | 發票金額比實付多或少五十元 | 沒錯→「好，謝謝。」；錯→「不好意思，發票上的金額好像不對，應該是○元吧？」 |

四關都用共用的 `catchState`／`payStates`：①沒錯／謝謝　②有禮貌指出問題（對方沒錯時，數字是錯的）　③沒禮貌（永遠錯）。抓到錯之後加油員道歉並補（更正油種／金額、報對價錢、補找錢、重印發票）。
**ORDER 關是「先記下來」的關卡**：玩家說錯油種或金額，會扣十分（寫進錯誤紀錄），但不擋住，遊戲照他「實際說的」往下走（複誦、加油機螢幕、價錢、發票都用實際說的算）。其他關卡（ARRIVE、FILL、CLOSE）是固定正解、選錯留在原關（跟其他遊戲一樣）。

## 價錢與計算邏輯

- 實際應付 `t.total` ＝玩家在 ORDER 關**實際說的金額** `t.oAmt`（加油是「加多少錢」，不是加多少公升）；Ami 要的 `t.amt` 另外記。公升數只用來顯示：金額 ÷ 每公升價（92：31.2、95：32.7，2026-11-02～08 中油牌價，待確認），取小數兩位。
- 報價 `t.said`＝總價或總價加五十／三十元（共用 `initPay`）；你給的鈔票永遠是五百元（`billFor`）；找零 `t.change` ＝ 500 − total，實際找的 `t.given` 可能差十或二十元。
- 發票金額 `t.invSaid`＝總價，或總價加／減五十元。

## 正解怎麼判定

好結局＝錯誤 ≤ 2 次，**而且最後實際加的油種與金額和 Ami 要的完全一樣**（`t.oFuel===t.fuel && t.oAmt===t.amt`）。所以玩家在 ORDER 關說錯，即使其他都對，也是壞結局，Ami 會說「我要的是…怎麼加成…」。
