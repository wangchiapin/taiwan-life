## 1. 先做什麼

1. 複製一個最新的遊戲當範本：`games/noodle`（有「對方出錯」和付錢找錢）或 `games/mrt`、`games/street`。
2. 只改遊戲自己的部分：`GAME = {…}`、資料、台詞、關卡（`getConfig()`）、小字典、提示、音樂。共用的功能（計時、扣分、綠卡、排行榜、成績上傳、設定、翻譯、朗讀、拼音）不要複製。
3. 先把劇情流程寫給 Ben 看，確認後才寫程式。台詞和拼音第一版是草稿，Ben 會審。

## 2. 每個遊戲都要有的設定

- 場景 ID：資料夾名 = `scene` = 排行榜前綴。排行榜 collection 叫 `<scene>game_scores`，**不能改名**。
- `GAME = { scene, track, settingsKey, roles }`：場景 ID、GA4 名稱、存設定的 localStorage 名稱、朗讀角色的音高。
- 三種語言：台詞一律用 `L(中文, 西文, 英文)`。繁體／簡體、西文／英文由玩家設定決定。
- 拼音用台灣讀音。讀錯的字加進該遊戲的 `customPinyin`。統一：「和」念 hàn、「嗯」念 ēn。
- 分數：100 分起，每個錯誤 −10。`Game.addMistake()` 扣分、`Game.good()` 出綠卡。
- 結局：錯誤 ≤ 2 次是好結局，否則壞結局（冰淇淋店另有更多條件）。結局後進結果頁，呼叫 `uploadResult()` 上傳成績。
- 星星（地圖用）：0 次錯誤 ★★★、1–5 次 ★★、6 次以上 ★。
- 背景音樂：每個遊戲最後一行 `Music.init({…})`，**不能跟別的遊戲同一首**。

## 3. 玩家角色與語氣

- 玩家是「主角」，名字由玩家輸入。西文對玩家說話不分男女（不用 listo／solo／bienvenido 這類有性別的字）。
- 畫面上主角看不出性別、看不到臉（手可以）。
- Ami 是固定的朋友，會用 LINE 交代任務。店員招呼用「¡Hola, buenas!」。
- 台詞要是台灣人真的會講的說法，流程要符合 2026 年台灣現場（悠遊卡、LINE Pay、發票、載具、叫號）。
- 中文價錢報「一百五十元」這種念法；2 在量詞前念「兩」。

## 4. 關卡設計原則（Ben 10/27 決定，一定要照）

新遊戲不能只是「照 Ami 的話選就對」。每個遊戲至少要有：

1. **對方會隨機出錯**：報價、複誦、找錢、拿給你的東西、印出來的票，一部分機率是錯的（約 40–50%），玩家要自己核對。
2. **抓錯和沒錯都要做成正解**：對方說對時，「不對，我要的是…」是錯誤選項；對方說錯時，「好，謝謝」才是錯誤選項。
3. **三個選項的固定寫法**：①沒錯／謝謝　②有禮貌地指出問題（含具體正確的數字或內容）　③罵人或沒禮貌的說法（永遠是錯誤選項）。
4. **抓到錯誤之後要有後續**：對方道歉、補錢、重做、重印，不能一句話結束。
5. **綠卡**：做對才出現，放在下一頁對話上方，不另外多一個過場頁。
6. **選了什麼先記下來，最後才判定**：不要當場擋住；錯誤在結局統一說明。
7. **價錢照實際做出來的算**：不要用 Ami 訂單的總價。
8. **新增需要補的圖**，先記在 `docs/image-todo.md`，最後一起做。

共用寫法（麵店、超商、鹽酥雞已經在用）：
- `catchState()`：一關「①沒錯 ②有禮貌指出 ③沒禮貌」，由 `wrong()` 決定這次對方有沒有出錯。
- `payStates()`：報價（PAY）、重算後付錢（PAY_FIX）、找錢（CHANGE）三關。付的鈔票由 `billFor()` 決定（一百、兩百、五百）。
- 錢的文字小工具：`money`、`esM`、`enM`、`zhNum`。2 念「兩」用 `NZ`。

## 5. 畫面規則

- **任務提示**面板：只放畫面上沒有的資訊。固定有 Ami 的 LINE，和「我的狀況」（身上的錢、手上的東西）；NPC 的話只留答題需要的數字（價錢、路線、天數），客套話不放。
- **過場頁**順序：圖 → 綠色回饋卡 → 旁白 → 過場按鈕。旁白要對得上圖。按鈕文字寫在 `NEXT_LABEL`（key 是下一關的名字）。
- 不要放「📝 Mi situación」按鈕（內容已在任務提示裡）。
- 沒有圖時自動顯示 emoji，所以先寫程式、圖之後補都可以。
- 小字典 `VOCAB`：每個詞都必須在該關畫面或台詞裡真的出現，先 grep 確認。LINE 裡的詞歸在 START。
- 手機：`<meta viewport>` 要有 `maximum-scale=1`，不要 `viewport-fit=cover`；`<html>` 加 `html{color-scheme:light}`。

## 6. 圖片

- 正方形 `.jpg`，**720×720**，品質約 84，檔名小寫，放 `games/<scene>/images/`。麵包店的物品小圖是 240。
- 常用檔名：`start`、`end_good`、`end_bad`、`result`，加每關自己的圖。對方出錯被抓到的尷尬表情用 `*_sorry.jpg` 或 `*_oops.jpg`（沒有就自動用原圖）。
- 做圖提示詞：一次一張，Ben 確認才做下一張；每個提示詞都要完整、可直接複製；寫清楚鏡頭方向、高度、角度；Ami 長相要跟飲料店的 Ami 一樣；場景要符合劇情真正發生的地點。

## 7. 測試

- 每個遊戲要有 `tools/oracles/<遊戲>.py`：依「對方有沒有出錯」給出正解。
- `python3 tools/smoke.py perfect <遊戲>` 照正解玩，多跑幾次（隨機）都要 100 分；另外跑 `mixed`、`embed`、`trans`。
- 改共用檔時，用 `tools/compare_shots.py <遊戲> <舊檔>` 逐畫面比對。
- 測試要覆蓋：對方出錯、對方沒錯、玩家抓到、玩家沒抓到、付錯錢、順序錯。
